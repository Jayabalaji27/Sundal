## 1. Main root cause: permission flags were "all true" for managers, members and clients

Every self-registered account gets `users.type = 'company'` in SaaS mode. That includes invited managers, members and clients.

`App\Traits\HasPermissionChecks` gave **full access** to any user with `type === 'company'`. Because of that, every `can*` and `permissions` flag that controllers send to the pages was `true` for those roles. Examples:

- `canDeleteProject`
- budget `create/update/delete`
- timesheet `approve`
- contract `delete`
- task `update/assign_users`

Some actions were also allowed on the server when they should not have been. For example, a member could update a task created by someone else.

**Fix:**

- Added `User::hasWorkspacePermission()`.
  - The owner of the current workspace (and superadmin) gets full access.
  - Everyone else gets the permissions of their **role in the current workspace**. This is the same rule as `HandleInertiaRequests::getUserPermissions()`, which the frontend already uses.
- `HasPermissionChecks` now uses `hasWorkspacePermission()`, so all controllers that use the trait now return correct flags.

## 3. Decisions made (please confirm)

1. **Member tasks:** members can view all tasks on their projects, but can only change tasks they created or are assigned to.
2. **Client tasks:** clients see tasks only when the project's shared settings turn on Task.
3. **Project delete:** blocked while the project has invoices. Everything else is deleted with the project, as before, and bugs are now deleted too.
4. **Plan limits:** 0 means *unlimited* for users, clients and storage. This is how the code already behaved; it is now documented in the form.
5. **Meeting menu items:** not hidden when the integration isn't configured. The Zoom settings note now describes the real behaviour instead.
6. **Member dashboard budget widget:** kept. Members have view-only access to budgets on their own projects. The figure is now correct.

```bash

```

The migration `2026_10_02_000001` marks stages named Done, Completed or Complete as completed. In a workspace with none of those, it marks the last stage. It then sets the progress of tasks already in those stages to 100%.
